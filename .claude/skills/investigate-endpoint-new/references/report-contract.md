# 报告契约

## 一、概念模型

- **I 卡**：一个独立入站操作，例如 HTTP 路由、gRPC method、MQ 消费者、定时任务或 CLI 命令。同一 handler 的多个等价路由可合并；语义独立的轮询入口应拆卡。
- **O 卡**：主链路中的一个业务操作或交互单元。一张卡可包含为同一业务目的紧密协作的多个调用，但必须写出内部顺序。
- **进程内卡**：重要内部计算可使用 O 编号，标题必须标注「进程内，无外部系统」，且不计入外部依赖。
- **span**：仅作可选可观测性映射，不再用于定义卡片。O 卡不必然等于一个 client span。

I 与 O 使用独立编号空间。O 编号是稳定引用 ID，默认按主成功路径首次出现顺序分配，**不代表所有分支的全局运行时全序**。真实顺序由处理逻辑及条件、循环、并行、异步标注表达。

## 二、报告骨架

```markdown
# {METHOD /path、RPC method 或其他入口} 调查报告

## Executive Summary
- 调查范围：{源码根、版本、静态／动态、入口}
- 功能：{业务语义与主成功路径}
- 外部依赖：{O 编号、类型、目标；计数时说明口径}
- 注意：{主要风险或限制，按重要性排序}

## Inbound
### I1. {类型} → {路由／Topic／触发源}

## Operations
### O1. {类型} → {目标}
### O2. …

## 未解析项（仅有影响结论的缺口时出现）
## 补充说明（仅跨卡片信息，可选）
```

坐标前缀在调查范围中声明一次。报告语言跟随会话，协议关键字和代码标识符保留原文。

## 三、摘要与卡片

Executive Summary 应独立说明功能、主链路、外部依赖和主要风险。摘要可以重复最关键的事实，不要求机械地「全文只出现一次」；避免的是无价值复述。

每张卡的最小集：

1. 编号、类型、目标；
2. 一句话结果摘要；
3. 主坐标；
4. 该卡独有的关键条件或风险（有才写）。

推荐结构：

```markdown
### O1. 下游 HTTP → 库存服务

主坐标：`client/StockClient.java#deduct`

> 扣减库存；失败传播到 I1 的错误翻译层。

**关键事实**
- 未显式配置超时；依据：{依赖版本与配置证据}
```

文件或 GFM 环境可用 `<details>` 收纳字段契约、处理逻辑和失败表；终端中使用清晰小节即可。折叠是排版选择，不得用来隐藏最低覆盖所需的事实。

## 四、数据契约与流向

仅对有相应数据载体的卡片输出 Request／Response／Message／Value，不适用时整段省略。

- **字段契约**：列出所有有业务意义的真实字段及结构，不能用「订单信息」等泛称替代。
- **数据映射**：关键字段标来源 `←` 与去向 `→`；简单且显然的直通映射不重复描述。
- **Schema 校验**：与字段契约分开，记录机制与整体定义位置；字段级规则仅在其影响路由、分支、短路或失败处置时展开。
- **序列化**：按需记录 null 省略、命名策略、包装信封、二进制或 multipart 形态。

报文示例必须标明是「完整示例」还是「结构示意／节选」。标注为 `json` 的代码块必须是语法有效的 JSON；状态码写在代码块外，动态值使用字符串占位符或其他合法 JSON 值。语义完整性由字段契约保证，不靠超长代码块保证。

## 五、控制流与失败语义

处理逻辑用短步骤表达，并直接标注：

- `条件：{触发条件}`；
- `循环：{次数或集合}`；
- `并行：{并行组}`；
- `异步：{是否等待结果}`；
- `短路：{终止条件}`。

步骤数量以清晰为准，不为满足字数而合并成难以理解的长句。

Inbound 错误映射建议包含：场景、来源、对外响应、泄漏。来源可按实际使用「本地校验／业务处理／鉴权／下游传播／平台或框架／未捕获」，不要强行把本地 IO 故障归入校验收。

Outbound 失败记录建议包含：症状、本地处置、向 Inbound 的传播。重试、降级、忽略、清理和告警按源码事实描述，不为了枚举整齐而牺牲语义。

鉴权机制写在卡片元信息；鉴权失败如何映射仍可进入错误表。错误分支追到实际翻译层，项目特有的非标准映射如实记录。

## 六、证据与坐标

每卡一个主坐标作为默认验证入口。以下关键主张还应有直接证据坐标或明确来源：

- 路由、字段、SQL、命令和报文；
- 超时、重试、熔断、TTL 等数值；
- 框架或依赖默认行为；
- 鉴权、隐式出站、敏感数据和错误翻译；
- 派生 SQL 或其他非直接字面值结论。

优先使用 `路径#方法`；行号只有在版本固定时才更可靠。路径相对已声明前缀，格式统一为 `文件:行`、`文件:起-止`、`文件#方法` 或整文件路径。不要为减少坐标数量而删掉不可替代的证据。

代码块只保留字面值即结论的内容，例如 SQL、协议报文、命令、配置键和字段结构。函数体与大段实现用意图和坐标替代。代码块长度以足够核验为准，不设置与卡片数绑定的机械上限。

## 七、不确定性与省略

- 未发现的内容不写；无业务意义的空字段不填「无／N/A」。
- 「无鉴权、无幂等、无超时」等会改变调用方判断的负面事实必须写。
- 已调查但材料不足时写「未解析」，说明已确认范围和受影响结论。
- 未调查的可选深层机制不需要逐项声明。
- 不通过删去负面事实或不确定性来满足简洁要求。

## 八、最终人工复核

自动校验后，再确认：

- 事实与当前源码版本一致，派生和外部默认已标注。
- 卡片集与调用图一致，没有漏卡或凭空多卡。
- 数据契约、关键映射、失败处置和错误翻译完整。
- 编号只承担引用，控制流没有被编号误导。
- 摘要可独立阅读，细节可核验，敏感值未泄漏。
