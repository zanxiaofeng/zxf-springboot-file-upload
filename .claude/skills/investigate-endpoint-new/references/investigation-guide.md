# 调查执行指南

## 一、预检与范围

开始前确定：

- 源码根与目标模块；monorepo 中不要跨模块误配路径。
- 目标入口的 method、路由模板、RPC method、topic、cron 或命令。
- 调查目的：默认链路、故障排查、安全审查或依赖审查。
- 源码版本：优先记录完整 commit；无法取得时记录分支、文件快照或其他可复现标识。
- 可用材料：源码、生成代码、OpenAPI／proto、配置、测试和依赖版本。

多个候选入口都能匹配时，利用路由定义、测试和调用方消歧；仍不唯一且会改变结论时再询问。只有部分源码时，将报告标为限定范围调查，并列出影响结论的缺口。

## 二、证据台账

调查时维护内部台账，不把台账原样塞进最终报告：

| 类别 | 至少记录 |
|---|---|
| 入口 | 路由、handler、鉴权、前置限制、主坐标 |
| 调用图 | 调用方 → 被调方、条件、顺序、并行／异步关系 |
| 交互 | 类型、目标、协议、直接证据、所属入口 |
| 数据 | 字段来源、转换、消费去向、序列化规则 |
| 错误 | 原始失败、捕获层、翻译层、最终对外语义 |
| 缺口 | 未解析项、已尝试线索、对结论的影响 |

先完成最低覆盖，再写最终正文。台账用于防止重复阅读和遗漏，不要求用户看到。

## 三、入口定位速查

- **Spring MVC／WebFlux**：`@RestController`、`@RequestMapping`；contract-first 项目同时查生成的 API 接口和 `openapi.yml` 的 `operationId`。
- **Node**：Express 路由、NestJS `@Controller`；Next.js 查 `pages/api/**` 或 `app/api/**/route.ts`。
- **Python**：Django `urls.py`；FastAPI 路由装饰器。
- **Go**：`http.ServeMux`、gin／echo 等路由注册点。
- **Rails**：`config/routes.rb`。
- **gRPC**：`.proto` service 与 handler 实现。
- **MQ／定时／CLI／事件**：消费者注册、订阅声明、cron、命令入口和事件监听注册点。

通用反查线索：路由片段、topic、OpenAPI `operationId`、API 测试、调用方和配置键。

## 四、调用链与横切机制

主路径优先沿直接引用关系调查，直到本服务进程边界。纯转发层之后仍有编排时继续下行。

以下不是可一概放弃的「底层细节」：

- 鉴权、授权、请求体限制和输入净化；
- 全局异常翻译和响应改写；
- 会短路主链路的 Filter／Interceptor／AOP；
- 会产生隐式出站或后台工作的框架机制。

连接池内部、动态代理实现细节等与行为无关的底层内容不展开。安全审查模式下，额外检查 Filter、Interceptor、AOP、事件链、`@Async`、客户端拦截器和依赖版本。

## 五、证据等级与来源优先级

按以下优先级取证：

1. 当前版本的源码、配置和契约；
2. 当前版本生成代码、测试和依赖锁文件；
3. 与依赖版本匹配的官方源码或文档；
4. 基于明确规则的派生结论；
5. 无法证实的内容标为未解析，不写成事实。

建议标注：

- **已实证**：有直接源码或配置证据。
- **派生**：由 ORM、代码生成器或框架规则推导，写明推导依据。
- **外部默认**：来自特定依赖版本，写明版本和来源。
- **未解析**：当前材料不足，并说明影响。

ORM 派生 SQL 不等于已在数据库执行验证；框架默认值也不能脱离版本和配置覆盖关系凭空断言。

## 六、交互边界

- **外部交互**：下游 HTTP／gRPC、DB、缓存、MQ、SMTP、对象存储、自定义网络协议等。
- **本机交互**：有业务意义的文件系统读写和子进程。
- **进程内重要操作**：大报文解析、加解密、媒体转码等；可编号保序，但必须标注「进程内，无外部系统」。

只展开本服务直接发出的一跳。下游自己的依赖不进入本报告；用户要求跨服务 trace 时，按服务拆报告或明确层级。

异步受理若依赖轮询、回调或消息通知才能表达终态，应调查该伴随通道。轮询查询是独立入口时单独建 I 卡，并说明它与原入口的关系。

## 七、覆盖门禁与停止条件

成稿前确认：

- 所有相关入口、鉴权和前置限制已覆盖。
- 主成功路径和每个直接交互已归属到调用图。
- 关键 Request／Response／Message 字段及映射有证据。
- 失败分支已追到实际翻译层，而非按惯例猜状态码。
- 条件、并行、循环和异步关系没有被单一编号掩盖。
- 关键缺口已补齐，或以「未解析」呈现其影响。

满足最低覆盖后停止深入无关框架内部。不要为了追求表面完整而读取整个仓库。

## 八、安全与执行边界

默认只做静态源码阅读，不启动或调用目标服务，不向目标下游发送请求，不修改目标业务代码。若用户另行要求动态验证，应明确区分静态结论与运行结果。

读取依赖源码或官方文档时遵守当前环境权限；网络不可用时使用本地材料并降低证据等级。凭证值、令牌、密钥、敏感个人数据一律使用 `{来源}` 或 `{占位符}`，配置键名和密钥管理来源可以保留。
