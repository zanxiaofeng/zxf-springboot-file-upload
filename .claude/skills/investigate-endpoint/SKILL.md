# Investigate Endpoint — API 执行链路调查报告

## 产出目标与总原则

产出 = **Executive Summary + Inbound 卡片（通常 1 张；多入口时 I{n}）+ N 张 Outbound 卡片**。概念模型：1 个 server span（Inbound）+ N 个 client span（Outbounds）；path 用路由模板（`/api/users/{id}`）。服务于接口文档化、新人 onboarding、故障排查、安全与依赖审查。

**原则一（结论优先）**：报告是「结论 + 验证入口」，不是「源码摘要 + 逐句脚注 + 全量填表」——主阅读路径（Summary + 每卡一句话摘要 + 关键事实）只放结论；证据按风险配额发放；细节折叠；schema 项按需选取，无内容即整段省略。

**原则二（数据优先，报告视角 = 数据流动）**：第一位是数据本体与数据映射的**整体表达**——Request / Response 的 **Body**（真实字段、真实结构完整实证）与**字段流向**（来源 `←` / 去向 `→`，以及错误映射表、失败处置表等 Mapping 形态）；**单个字段的 check 默认不关注**，仅当它影响关键处理流程（决定路由 / 分支 / 短路 / 处置去向）时才写，且写成流程事实而非校验清单；schema / 校验机制是随附信息——与 Body 分开表达、整体引用，勿混为一谈。

## 调查流程（先读完代码再写报告，禁止边读边猜格式）

1. **定位入口** — route 定义处（定位方法见 `references/investigation-guide.md`）。记录 HTTP method、path 模板、参数来源（path / query / header / cookie / body）、入站前置限制（请求体上限、过滤器/中间件、认证授权）。
2. **沿调用链下行** — handler → 应用/用例层 → 领域逻辑 → 基础设施客户端，直到进程边界。注意纯转发层（门面/代理）——真正的编排在它下一层，别在此停。
3. **识别出站交互** — 判定标准：**跨进程 / 跨网络 / 跨信任边界**（网络出站、本机出站、进程内重计算三类，细则见 guide）；只展开本服务直接发出的一跳。
4. **实证提取协议真实格式 + 追踪数据流** — SQL / 命令 / 报文一律从客户端代码**实证提取**，禁止臆造；动态值写 `{占位符}`；配置默认值与覆盖关系交叉核实，`${ENV:default}` 原样保留。同步追踪**字段流向**：入参字段 → 出站请求字段 → 出站响应字段 → 最终响应字段——数据映射是调查动作，不是写报告时回补的。
5. **识别控制流** — 短路（管道/责任链/校验链）、条件分支（开关/feature flag）、并行、异步、弹性（超时/重试/熔断）、背压（信号量/连接池/限流）。决定 Outbounds 编号次序与标注方式。

## 输出骨架（强制，违反即不合格）

```
# {METHOD /path 或 RPC method} 调查报告

## Executive Summary
- 功能：{一句话业务语义}
- 外部依赖：O1（{类型} → {目标}）、O2（…），一行说完；进程内卡不属「外部」，另起一短句「进程内：O{n}、O{m}」（有才写）
- 注意：{最值得注意的风险 0–3 条：无超时 / 错误泄漏 / 异步旁路 / at-most-once 丢消息…}

> 坐标相对于 `{共享路径前缀}`。

## Inbound
### I1. {类型} → {路由 / Topic / 触发源}
## Outbounds（{短路 / 并行 / 背压等全局控制流，一行；无则省略括注}）
### O1. {类型} → {目标}
### O2. …
## 补充说明（可选，只放跨卡片信息）
```

读者不展开任何折叠区即可从 Summary 获得 80% 关键信息。

## 卡片结构（主路径 + 折叠区）

每张卡片两层，主路径（折叠区外）≤ 10 行（按渲染行计，不含空行），四件：

1. **标题承载身份**：`### {编号}. {类型} → {目标}（{关键属性}）`——类型细分到协议/库（`MQ → orders topic（Kafka 异步生产者）`）、关键属性（异步/条件/循环等）写进标题；标题已含的信息不再进表。一张卡片 = 一个业务动作（不拆卡，a/b 子条目、独立编号空间等细则见 formats.md §二）；`O{n}` 的 n = 运行时执行次序
2. **小元信息表**：只收标题未覆盖的身份字段（HTTP 卡「路由」、DB 卡「表」、I 卡「鉴权」等 0–2 个）+ **主坐标**（必有）；身份字段为 0 时**不建表**，主坐标单独一行；字段名词化、值枚举化（`鉴权=JWT`、`表=orders`），禁止自然语言句子
3. **一句话摘要**（引用块）：只回答「它对外承诺什么结果」，可含 `→` 流程速写（`校验 → 扣库存 → 落单`），不展开分支细节
4. **关键事实** ≤ 3 条：只收「读者猜不到、且影响行为」的内容（超时未配置、非标准错误码、幂等键缺失、异步旁路、feature flag 条件执行…）；L2 风险坐标在此标注

**折叠区**（环境自适应：输出到文件 / GFM 环境用 `<details><summary>{内容清单}</summary>…</details>`；输出到终端用 `▸ {内容清单}` 标记行 + 一级缩进代替——正文行缩进 2 空格，表格与代码块顶格不缩进（保 GFM 渲染兼容），`▸` 行即折叠区边界）：完整元信息（触发条件/幂等/保护机制按需）、处理逻辑详版、类型专属 schema（Request/Response、SQL、报文…）、失败表、源码片段——全部按需，无实质内容的小节不出现。菜单见 `references/formats.md`。

## 密度与证据配额（硬上限，细则见 formats.md §二/§三）

- **处理逻辑**（折叠区内）：①②③ 编号，每步动词开头 ≤ 30 字，≤ 5 步——超出先合并为更高层意图；步骤之间不用箭头、禁「然后/随后/接着」（步内 O 编号链可用 `→`，如「管道 O2→O3→O4」）；不展开下游内部（写「调用 O2」即可）；控制流行内标注：`②（循环：逐商品 2N 次）`、`③（与 ② 并行）`、`④（条件：flag 开启时）`、`⑤（异步：不等结果）`；摘要已承载流程的简单卡整段省略
- **代码块**：主路径（折叠区外）**零代码块**；块级引用白名单只有「字面值即事实」者（SQL、路由/URL、请求/响应报文、配置键、注解、topic）且只进折叠区、每段 ≤ 5 行；行内标识符引用（`orderService.deduct()`）每卡 ≤ 5 处
- **坐标**：三层——L1 主坐标每卡恰好 1 个（元信息表）；L2 风险坐标每卡 ≤ 2 个（关键事实内）；其余结论 0 个（L1 兜底）。每卡合计 ≤ 3 个，坐标 + 行内代码每卡 ≤ 5 处；同文件多处合并为区间或方法级；路径去共享前缀，格式统一 `文件:行` / `文件:起-止` / `文件#方法` / `文件`（整文件级——一个文件一个 handler 的路由文件等）
- **事实唯一**：任一事实完整描述只出现 1 次，别处编号引用；跨卡片共性二选一——Summary 完整写一次（各卡不再写）或 Summary 一句带过（拥有卡写完整），选定后不得混用；补充说明只放跨卡片信息，禁止复述单卡内容
- **无空壳**：按需 schema 项无实质内容时整段省略——省略 ✅，置「无/不适用」❌，写「无特殊错误映射」❌❌；默认值（默认无限流/无重试）、显然行为（GET 无请求体）、必然推论（写了 `@Transactional` 不再单列回滚）一律省略；「无 X」只在属于「会猜错的无」（读者默认它存在而实际没有）时出现

## 输出前自检（强制，逐条机械核对）

正确性：

- [ ] 每个协议细节（参数名、报文、SQL、默认值）调查时已实证，无臆造；依据是否印出由坐标配额定，不逐句脚注
- [ ] `O{n}` 编号 = 运行时执行次序；短路 / 循环 / 条件 / 异步已标注（行内标注或触发条件）
- [ ] 编号闭环：每个 O 卡片被至少一个 I 或上游 O 引用；无悬空引用、无孤儿 O
- [ ] 数据流动完整：I/O 卡 Request / Response Body 均真实字段实证，关键字段有来源 / 去向标注（`←` / `→`）或消费说明；Body 数据与 schema 校验未混写在同一条目
- [ ] 进程内 vs 真实出站有区分标注；语言跟随会话语言（HTTP 动词、SQL 关键字、协议命令保留英文）

密度：

1. 无空壳段落：不存在「有标题、无实质内容」的字段/段落；schema 项无内容时整段省略，而非置「无」
2. 按需项只写非默认、非显然、非推论的内容
3. 每卡最小集齐全：编号、类型、目标、一句话摘要、主坐标
4. 处理逻辑每步 ≤ 30 字，步骤间无箭头无「然后/随后/接着」（步内 O 链的 `→` 除外），≤ 5 步，不展开下游内部
5. Outbound 失败表只有两列（症状 | 处置），处置列为枚举词（致命-中止 / 降级-跳过 / 重试{N}次 / 忽略-记日志），不含句号；Inbound 错误映射表列式见 formats.md §二
6. 任一事实出现次数 ≤ 1（编号引用与 Summary 一句带过除外）；补充说明不复述卡片内容；主路径加粗仅「关键事实」引导词一处，折叠区字段组加粗不限
7. 折叠区外无代码块；每段代码 ≤ 5 行；代码块总数 ≤ 卡片数
8. 每卡首处坐标必为「主坐标」；每卡坐标 ≤ 3；处理逻辑区坐标 = 0（折叠区源码除外）
9. 同文件多处已合并为区间或方法级；路径已去共享前缀、无 `L88` 变体；坐标 + 行内代码每卡合计 ≤ 5 处
10. 删任一代码块 / 非锚点坐标后结论仍成立 → 该证据不合格，删
