# 回归评测协议（evals）——本 skill 规则改动的质量闸门

> 改本 skill 的任何规则（SKILL.md 原则 / 调查流程 / 输出骨架 / 配额 / 自检，或 `references/*`）后，按本协议重跑金标准案例并比对输出——没有回归比对的规则修改是盲改。本文件是**给执行修改的会话看的操作协议**，不是调查报告的组成部分。

## 一、金标准案例（各采用项目自建）

金标准 = **你项目内可本地实证的代表性端点** + 人工复核过的基准报告。建基方法：

1. 选端点：优先选覆盖面广的（多出站类型 / 异步或轮询形态 / 错误通道分段），一次建基覆盖更多规则面；
2. 首跑：按第二节执行一次完整调查，人工逐项复核事实与结构后，将报告存档为基准（可放本目录，如 `baseline.md`）；
3. 密度参照：`references/example.md` 三份范例（A 分布式 / B 单体 CRUD / C 异步受理）即基准应有的密度与形态。

> 示例：项目若有 202 受理 + 轮询端点，参照案例 C 的形态建基，可一次覆盖异步受理、通道分段错误映射、轮询语义等高漂移面。

## 二、重跑步骤

1. **固定输入**（防输入措辞漂移导致 diff 噪音）：在无基准记忆的子代理中发起调查，prompt 模板一字不差（仅替换端点）：

   > 请调查 {METHOD /path} 端点的完整执行链路并产出调查报告

2. **防自我污染**：重跑会话**禁止阅读** `references/example.md`（含范例答案）与 `evals/` 目录下**全部**文件（含基准存档与本协议——判分维度含预期结构提示，读了构成提示泄漏）——调查必须从源码独立实证，否则比对的是复述能力而非规则效果。
3. **产出比对**：重跑报告落盘 `evals/runs/run-{date}.md` 供追溯（runs/ 目录按日期累积），与基准逐卡 diff。

## 三、判分（rubric，非逐字匹配）

| 维度 | 判据 | 判读 |
|------|------|------|
| 事实准确 | 每个协议细节（路径 / 报文 / 配置值 / 熔断参数 / TTL）与源码一致；错一处即 FAIL | 任一 FAIL = 规则改动引入回归 |
| 结构合规 | 输出骨架、卡片最小集、主路径 ≤ 10 行、坐标 / 代码块 / 事实配额全部符合改后规则 | 违反项 = 规则表述有歧义或约束力不足 |
| 覆盖完整 | 卡片集与基准一致（无漏卡、无凭空多卡）；基准标注的关键事实与控制流无遗漏 | 漏卡 = 调查流程指引缺口 |

**diff 归因（关键区分）：**

- **规则回归**：重跑输出在事实或结构上劣于基准 → 修规则或回滚改动；
- **代码演进**：仓库代码已改导致基准过时（如配置值、阶段数变化）→ **更新基准存档**而非判 FAIL——基准追随代码，评判的是规则；
- **表达等价**：措辞不同但事实 / 结构 / 密度同档 → PASS，不追求逐字一致。

## 四、出口

- 全维 PASS → 修改可保留，本次回归结束；
- 任一 FAIL → 修复后重跑至全过；连续 2 轮仍 FAIL → 向用户报告 diff 与怀疑点，由用户裁决规则取舍。
