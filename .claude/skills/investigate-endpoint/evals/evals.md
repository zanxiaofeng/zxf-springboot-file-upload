# 回归评测协议（evals）——本 skill 规则改动的质量闸门

> 改本 skill 的任何规则（SKILL.md 原则 / 调查流程 / 输出骨架 / 配额 / 自检，或 `references/*`）后，按本协议重跑金标准案例并比对输出——没有回归比对的规则修改是盲改。本文件是**给执行修改的会话看的操作协议**，不是调查报告的组成部分。

## 二、重跑步骤（案例 C）

1. **固定输入**（防输入措辞漂移导致 diff 噪音）：在新会话 / 子代理中发起调查，prompt 一字不差：

   > 请调查 POST /api/files/async/upload 端点的完整执行链路并产出调查报告

2. **防自我污染**：重跑会话**禁止阅读** `references/example.md`（含基准答案）与 `evals/` 目录下**全部**文件（本协议的判分维度含预期结构提示，读了构成提示泄漏）——调查必须从源码独立实证，否则比对的是复述能力而非规则效果。
3. **产出比对**：重跑报告落盘 `evals/runs/run-c-{date}.md` 供追溯（runs/ 目录按日期累积），与基准（example.md 案例 C）逐卡 diff。

## 三、判分（rubric，非逐字匹配）

| 维度 | 判据 | 判读 |
|------|------|------|
| 事实准确 | 每个协议细节（路径 / 报文 / 配置值 / 熔断参数 / TTL）与源码一致；错一处即 FAIL | 任一 FAIL = 规则改动引入回归 |
| 结构合规 | 输出骨架、卡片最小集、主路径 ≤ 10 行、坐标 / 代码块 / 事实配额全部符合改后规则 | 违反项 = 规则表述有歧义或约束力不足 |
| 覆盖完整 | I1/I2/O1–O6 无漏卡；错误通道分段两段表齐全；轮询语义三要素（占位 / TTL / 淘汰后行为）在 | 漏卡 = 调查流程指引缺口 |

**diff 归因（关键区分）：**

- **规则回归**：重跑输出在事实或结构上劣于基准 → 修规则或回滚改动；
- **代码演进**：仓库代码已改导致基准过时（如配置值、阶段数变化）→ **更新基准**（example.md 案例 C 同步改）而非判 FAIL——基准追随代码，评判的是规则；
- **表达等价**：措辞不同但事实 / 结构 / 密度同档 → PASS，不追求逐字一致。

## 四、出口

- 全维 PASS → 修改可保留，本次回归结束；
- 任一 FAIL → 修复后重跑至全过；连续 2 轮仍 FAIL → 向用户报告 diff 与怀疑点，由用户裁决规则取舍。
