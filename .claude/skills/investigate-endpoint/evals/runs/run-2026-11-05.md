# POST /api/files/async/upload 调查报告

## Executive Summary

- 功能：multipart 文件上传的**异步受理**——预检、staging 落盘后立即 202 返回 scanId，四阶段扫描管道（类型校验 → ClamAV → YARA → 文档威胁）在虚拟线程后台执行，终态经轮询端点 I2 查询
- 外部依赖：O1（文件系统 → staging 暂存区）、O3（自定义 TCP → ClamAV clamd INSTREAM）、O4（子进程 → yara CLI）、O6（文件系统 → 正式存储/隔离区）；进程内：O2（Tika 类型探测）、O5（POI 文档威胁解析）
- 注意：capybara SDK 无 socket 超时，ClamAV 挂起仅靠应用层 60s 限时 + 熔断兜底；结果缓存 TTL 30 分钟淘汰后轮询永远返回 SCANNING 占位；staging 落盘失败（磁盘满）对外表达为 400 而非 5xx

> 坐标相对于 `src/main/java/zxf/upload`。

## Inbound

### I1. 同步 HTTP → POST /api/files/async/upload（multipart 异步受理）

| 鉴权 | 请求体上限 | 主坐标 |
|---|---|---|
| 无 | 100MB / 请求 110MB（413） | rest/fileupload/FileUploadController.java:38 |

> 异步上传入口：预检 → 落盘 → 202 + scanId，扫描转后台虚拟线程。

**关键事实**
- 202 后一切终态走轮询 body 的 `status` 字段（引擎故障 fail-closed 表达为 `ERROR`，而非 502）
- 无幂等：重发同一文件产生新 scanId、多次落盘

<details><summary>Request / Response / 处理逻辑 / 错误映射表</summary>

**Request**
- Method / Path: `POST /api/files/async/upload`；Content-Type: `multipart/form-data`
- 参数: part 名 `file`（必填，缺失 400）
- **Body（数据承载）**: 单 part 文件字节流 + `originalFilename`（客户端可控，路径部分被 `cleanedName()` 剥离，仅用于展示名/扩展名提取）+ `size`（字节）
- **Schema 校验**: 无 Bean Validation / 无 schema 校验（会猜错的无）——入站约束全部为命令式预检（Checker → `UploadPolicy`：空文件、大小上限、扩展名白名单，违规 400）+ multipart 容器级限制（413 与业务 400 分开归因）

**Response — Success**
```json
{ "scanId": "{uuid}", "status": "SCANNING", "message": "扫描进行中" }
```
- `filePath` 为 null 省略（`@JsonInclude(NON_NULL)`）；`scanId` ← Executor 生成的 UUID（受理凭证，轮询 I2 的路径参数）

**处理逻辑**（请求线程内）
- ① 预检空文件 / 大小 / 扩展名白名单（委托 UploadPolicy）
- ② 落盘上传流到 staging（调用 O1）
- ③ 生成 scanId 并提交后台扫描（异步：不等结果，链路 O2→O3→O4→O5→O6）
- ④ 组装 202 回执

**错误映射表**（按通道分段：上半段为受理时 HTTP 错误；202 之后一切终态见 I2 轮询语义）

| 场景 | 来源 | 对外响应 | 泄漏 |
|---|---|---|---|
| 缺 file part / 非 multipart / 流打开失败 | 本地校验 | `400 {"code":"FILE_REJECTED","message":"缺少上传文件或请求格式非法"}` | 否 |
| 空文件 / 扩展名非白名单 | 本地校验 | 400 FILE_REJECTED + 具体原因文案 | 否 |
| 超容器级 100MB | 平台限制 | `413 {"code":"FILE_TOO_LARGE"}` | 否 |
| staging 落盘 IO 失败 | 下游传播（O1） | 400 FILE_REJECTED「文件暂存失败，请稍后重试」 | 否-内部路径仅日志 |
| 未预期异常 | 未捕获 | 500 INTERNAL_ERROR 固定文案 | 否-不回显 message |
</details>

### I2. 同步 HTTP → GET /api/files/async/scan/{scanId}（轮询查询，独立 server span）

| 鉴权 | 主坐标 |
|---|---|
| 无 | rest/filescan/ScanResultController.java:27 |

> 任何时刻返回当前状态：未完成或已淘汰返回 SCANNING 占位。

**关键事实**
- 结果保留 TTL 30 分钟（Caffeine expireAfterWrite，上限 10 万条）AsyncScanProcessor.java:41-44；淘汰后轮询不 404，永远返回 SCANNING 占位——客户端无法区分「进行中」与「已淘汰」
- 不存在 404 语义：scanId 格式非法 400（VALIDATION_ERROR），格式合法但不存在的 scanId 同样返回 SCANNING 占位

<details><summary>Request / Response / 轮询终态映射</summary>

**Request**
- Method / Path: `GET /api/files/async/scan/{scanId}`；Path 参数按 UUID 正则校验（`@Pattern`）

**Response — Success**（与 202 回执同构，`filePath` 仅 CLEAN 时出现）
```json
{ "scanId": "{uuid}", "status": "CLEAN", "message": "文件安全", "filePath": "{uuid}.{ext}" }
```
- `status` 枚举：SCANNING / CLEAN / INFECTED / REJECTED / ERROR
- `message` 按 status 派生：INFECTED → 「检测到威胁: {threat ← O3/O4/O5 检出描述}」；REJECTED → 「文件被拒绝: {reason ← O2}」；CLEAN 打标时 → 「文件安全（macro-flagged: …）」
- `filePath` ← O6 返回的存储文件名（UUID.ext，不含路径）

**轮询终态映射**（202 后，4xx/5xx 语义在此转移）
- 管道 Rejected（类型/扩展名/ZIP 炸弹）→ REJECTED
- 管道 Infected（ClamAV/YARA/ActiveX/PDF 动作/BLOCK 宏）→ INFECTED
- 全过或 Flagged（FLAG 宏）→ CLEAN（Flagged 时 `threat=macro-flagged` 透传）
- 引擎故障 fail-strategy=CLOSED → ERROR，message 固定「扫描引擎暂时不可用，请稍后重试」
</details>

## Outbounds（O2→O3→O4→O5 串行管道，首个非 Passed 短路；信号量 Semaphore(16) 统一背压（同步/异步共用闸门）；O1 在请求线程，O2–O6 在 @Async 虚拟线程）

### O1. 文件系统 → staging 暂存区（请求线程内）

| 目录 | 主坐标 |
|---|---|
| `${UPLOAD_STAGING:./data/upload-staging}` | infrastructure/fileupload/StagingService.java:42 |

> 把上传流同步落盘为 UUID 命名暂存文件，后续扫描只传 Path。

**关键事实**
- 落盘失败（磁盘满/IO）清理残留后对外 400 FILE_REJECTED 而非 5xx StagingService.java:47-53
- UUID 重命名 + 仅保留原扩展名（客户端文件名不进路径，防路径穿越）

<details><summary>操作序列 / 写入模式</summary>

**操作序列**
```text
mkdir   {staging}                            ← 应用启动时（构造器）
write   {staging}/{uuid}.{ext} ← multipart 流
delete  {staging}/{uuid}.{ext}               ← 仅失败清理
```

**写入模式**
- `Files.copy` 流式覆盖写，无 tmp+rename 原子性（失败路径由 catch 清理兜底）
- 目录创建失败启动即失败（IllegalStateException，fail-fast）
- 扩展名缺失时暂存文件名无后缀
</details>

### O2. 进程内（Tika + commons-compress）→ 类型校验与 ZIP 炸弹防护，无外部系统

主坐标：application/filescan/stage/FileTypeScanStage.java:43

> 内容探测 MIME → 白名单与扩展名一致性 → ZIP 流式解压计数防炸弹。

**关键事实**
- `detectedMime` 写入管道上下文供 O5 路由复用（不重复探测）；MIME 不符/扩展名不符/ZIP 超限 → 短路（→ O6 DISCARD，终态 REJECTED）
- ZIP 四重防护（条目数 1 万 / 单 entry 100MB / 累计 1GB / 压缩比 100:1）：不信任 header 声明大小，全部实际解压逐字节计数 FileTypeScanStage#inspectZip
- 探测/解压 IO 异常按引擎故障（SCAN_ENGINE_ERROR）上抛走 fail 策略，非业务拒绝（损坏 zip 同样 fail-closed）

<details><summary>处理逻辑 / 允许类型</summary>

**处理逻辑**
- ① Tika 探测文件内容 MIME
- ② 白名单与扩展名一致性判定（jpg/jpeg、txt/csv 互认）
- ③ ZIP 实际解压计数查四重上限（条件：MIME=application/zip）

**允许类型**（MIME → 主扩展名，`FileScanProperties.MIME_TO_PRIMARY_EXT`，共 14 类）
- pdf / docx / xlsx / pptx / doc / xls / ppt / jpg / png / gif / bmp / txt / csv / zip
</details>

### O3. 自定义 TCP → ClamAV clamd（INSTREAM，capybara clamav-client 2.1.2）

| 目标 | 主坐标 |
|---|---|
| `${CLAMAV_HOST:localhost}:${CLAMAV_PORT:3310}` | infrastructure/filescan/ClamAvScanner.java:76 |

> INSTREAM 流式病毒扫描，检出即管道短路隔离。

**关键事实**
- SDK 无 socket 超时配置，靠应用层限时 60s（虚拟线程 Future.get）+ 熔断兜底；被放弃的挂起任务阻塞在 socket read 至 TCP 超时 ClamAvScanner.java:32-36
- 熔断参数：计数窗口 10 / 最小 5 次 / 失败率 50% / OPEN 30s / 半开 3 次（超时计入失败率）ClamAvScanner.java:62-69
- 引擎故障（不可达/协议错/超时/熔断中）→ fail-strategy：CLOSED（默认）转 ERROR 终态；OPEN 降级放行、打标 scan-engine-degraded 入库

<details><summary>帧格式与会话 / 连接与超时 / 失败表</summary>

**帧格式与会话**（clamd INSTREAM）
```text
C: zINSTREAM\0
C: <4-byte BE 长度><数据>   （每块 2048B，整文件分块发送）
C: <4-byte 0>               ← 零长度块终止
S: stream: OK               ← 干净
S: stream: {病毒名} FOUND    ← 检出
```

**连接与超时**
- 每次扫描新建 SocketChannel，无连接池；单次超时 `${CLAMAV_TIMEOUT_SECONDS:60}`s
- 响应消费：FOUND → threat = 「ClamAV: {病毒名}」（→ I2 message）；OK → null 继续 O4

**失败表**
| 症状 | 处置 |
|---|---|
| 不可达/协议错/超时/熔断中 + fail-strategy=CLOSED | 致命-中止（终态 ERROR） |
| 同上 + fail-strategy=OPEN | 降级-跳过（CLEAN 打标入库） |
</details>

### O4. 子进程 → yara CLI（自定义恶意软件规则匹配）

| 命令行 | 主坐标 |
|---|---|
| `yara -s --fail-on-warnings {rules} {file}` | infrastructure/filescan/YaraScanner.java:50 |

> 启动 yara 子进程按规则集匹配，命中签名即短路隔离。

**关键事实**
- 退出码 0 = 执行成功（命中也算成功，会猜错）；命中以输出非空判定，签名取非缩进行首列
- 超时 60s `destroyForcibly`；stdout 排空宽限 5s（输出读取在独立虚拟线程，防子进程挂起时调用线程永久阻塞）
- `yara.enabled=false` 时整阶段旁路（条件执行，完整逃生舱）

<details><summary>命令行与参数 / 输入与输出解析 / 失败表</summary>

**命令行与参数**
```bash
yara -s --fail-on-warnings {rulesPath} {stagedFile 绝对路径}
```
- `-s` 打印命中串；规则路径默认 `classpath:rules/malware.yar`，启动时解压为临时文件（`yara-rules-*.yar`，deleteOnExit），非 classpath 前缀原样使用；enabled=false 不解析规则路径（规则缺失也能启动）

**输入与输出解析**
- 环境变量全继承；无 stdin（文件路径传参）；工作目录为服务进程 cwd
- 非缩进行首列 = 规则名 → threat = 「YARA: {规则名, …}」（→ I2 message）；缩进行 / 0x 前缀行为命中串内容（丢弃）

**失败表**
| 症状 | 处置 |
|---|---|
| 启动失败（无二进制）/ 超时 / 排空超时 / 退出码非 0 | 致命-中止（转 fail 策略，同 O3） |
</details>

### O5. 进程内（POI / java.util.zip）→ 文档威胁检测，无外部系统

主坐标：domain/filescan/documentthreat/DocumentThreatScanner.java:54

> 按文档格式路由三分支扫描，宏可 FLAG 放行、ActiveX/PDF 危险动作始终拦截。

**关键事实**
- 非文档格式直通（条件：`detectedMime`（← O2）属 officedocument / msword / ms-excel / ms-powerpoint / pdf）
- MACRO + macro-policy=FLAG（默认 BLOCK）→ Flagged：CLEAN 终态 + macro-flagged 打标透传客户端；ACTIVE_X / PDF_ACTION 不受策略影响始终 Infected
- PDF 扫描对 FlateDecode 压缩对象流无效（已知限制，深度检测由 O3/O4 字节级兜底）DocumentThreatScanner.java:21-22

<details><summary>处理逻辑 / 内存策略</summary>

**处理逻辑**
- ① 按探测 MIME 判定是否进文档分支
- ② OOXML：遍历 zip 条目名查 ActiveX/VBA（条件：ActiveX 先判，防 FLAG 放行绕过拦截）
- ③ OLE2：POI VBAMacroReader 提取宏，逐模块匹配可疑 token（条件：autoopen/shell/powershell 等 10 个）
- ④ PDF：1MB 分块 + 64B 重叠窗口扫 /javascript、/openaction、/launch

**内存策略**
- PDF 流式分块不整体加载；OOXML 仅遍历条目名；OLE2 宏模块逐模块匹配、不拼接全局副本
</details>

### O6. 文件系统 → 存储生命周期处置（入库 / 隔离 / 清理）

| 目录 | 主坐标 |
|---|---|
| 存储 `${UPLOAD_STORAGE:./data/upload-storage}` / 隔离 `${UPLOAD_QUARANTINE:./data/upload-quarantine}` | application/filescan/FileScanService.java:81 |

> 按管道结论查表处置 staging 文件：CLEAN 入库、INFECTED 隔离、其余清理。

**关键事实**
- 入库/隔离均 UUID 重命名，响应只回存储文件名不含路径（防内部路径泄漏，→ I2 `filePath`）
- 隔离 move 跨文件系统降级 copy+delete；仍失败文件滞留 staging（仅 ERROR 日志，无告警重试）FileStorageService.java:56-63
- 隔离目录权限 rwx------（POSIX），启动时创建

<details><summary>操作序列 / 失败表 / 数据流向</summary>

**操作序列**
```text
copy   {staging}/{uuid}.{ext} → {storage}/{uuid}.{ext}              ← CLEAN（fail-open 降级同）
move   {staging}/{uuid}.{ext} → {quarantine}/{uuid}.quarantined     ← INFECTED
delete {staging}/{uuid}.{ext}                                       ← REJECTED/ERROR/入库后清理
```

**失败表**
| 症状 | 处置 |
|---|---|
| 隔离 move 失败（跨文件系统） | 降级-跳过（copy+delete） |
| copy+delete 仍失败 | 忽略-记日志（滞留 staging） |

**数据流向**
- 存储文件名 → `ScanResult.details` → I2 `filePath`（受理凭证 scanId 的全生命周期：I1 生成 → O1–O6 消费 staging 路径 → I2 凭它查询）
</details>

## 补充说明

- 全链路无 Spring Security、无自定义 Filter/Interceptor（grep 实证）：multipart 大小限制是唯一入站前置；`GlobalExceptionHandler`（@RestControllerAdvice）承担 I1 受理段的异常翻译
- 结果缓存为纯进程内（Caffeine）：应用重启后所有 scanId 丢失，轮询一律返回 SCANNING 占位——异步受理无任何持久化
- 同步端点 `POST /api/files/sync/upload` 与本链路共用 O1–O6 及背压闸门，仅受理编排与响应组装不同（同步在请求线程内完成全管道，引擎故障直接 502）
