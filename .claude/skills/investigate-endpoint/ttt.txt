investigate-endpoint Skill 输出优化完整报告

0. 诊断总览

四轮 review 指向同一个根因的三个侧面：

现象 根因 对应解法
报告骨架被方法论证胀 SKILL.md 把「怎么查」和「怎么写」耦合 结构层：分离执行与输出
单卡信息密度过高 字段名词化、自由描述、多载体重复 字段层：动词化 + 枚举 + 单一符号
代码块泛滥 证据焦虑，用源码当凭据 代码层：坐标替代，折叠区收口
坐标泛滥 句级验证执念，按结论数量分配坐标 坐标层：锚点 + 风险配额

一条总原则：报告是「结论 + 验证入口」，不是「源码摘要 + 逐句脚注」。主阅读路径只放结论，证据按风险配额发放，细节折叠到按需展开。

优化按四层递进执行，每层可独立落地，叠加后报告篇幅通常下降 50–60%，信息量不损失。

---

1. 结构层：分离「执行指南」与「输出模板」

1.1 SKILL.md 瘦身

SKILL.md 当前同时承担「怎么查」和「怎么写」。拆分：

· 留在 SKILL.md：调查流程要点、输出结构契约（精简版）、强制自检。
· 移出：入口定位速查、隐式出站排查、安全边界、调查深度规则 → references/investigation-guide.md，SKILL.md 一句「执行调查时参考该文件」即可。

效果：报告骨架不再被调查方法干扰。

1.2 强制 Executive Summary

报告开头固定 3–5 行 bullet，结论先行：

1. 这个 endpoint 做什么（一句话业务语义）。
2. 依赖几个外部系统（O 编号 + 类型 + 目标，一行一个）。
3. 最值得注意的风险（无超时 / 错误泄漏 / 异步旁路等）。

读者不展开任何卡片即可获得 80% 关键信息。

1.3 卡片折叠式呈现

每张卡片主阅读路径只保留「一句话摘要 + 关键事实（≤3 条）」，完整元信息表、schema 细节、源码放入 <details> 折叠区。

1.4 元信息表字段合并

删除与专属子结构重复的字段：

· 删「失败处理」——失败分支只在失败表中出现一次。
· 删「下游依赖」——处理逻辑中的 O 编号即依赖声明。

元信息表只保留标题未覆盖的身份字段。

1.5 处理逻辑密度硬上限

· ≤ 5 步，超出必须合并为更高层意图描述。
· 禁止展开下游内部步骤——对方卡片的内容不在这里复述，只写「调用 O2」。

1.6 编号引用去重

同一事实在报告中出现次数 ≤ 1（编号引用除外）。「补充说明」只放跨卡片信息，禁止复述任何单卡已有内容。

---

2. 字段 / 语言 / 符号层：细颗粒度压缩

2.1 元信息表：动词化 + 枚举化 + 空值省略

· 字段名用单/双字动词：类型、入口、路由、鉴权、限流。
· 有限值域字段强制枚举，禁止自然语言：鉴权只允许 JWT / Session / API-Key / 无；限流只允许 无 / N次/秒 / 令牌桶。
· 空值整行删除，不写「无 / N/A / 不适用」。

```markdown
# 前
| 暴露方式/类型 | 同步 HTTP 接口 |
| 鉴权/保护机制 | JWT 鉴权，无额外限流 |

# 后
| 类型 | 入口 | 鉴权 |
| 同步HTTP | POST /api/orders | JWT |
```

2.2 标题承载身份，表内不重复

标题固定为 编号. 类型 → 目标（关键属性）；元信息表只保留标题未覆盖的字段。标题已含的「入口点」不再在表中重复。

2.3 处理逻辑：单序号、短句、无连接词

· 只用编号，不用箭头（避免两套顺序符号并存）。
· 每步动词开头，≤ 20 字。
· 禁用「然后 / 随后 / 接着」；并列用分号。

2.4 一句话摘要：一个主谓宾

摘要只回答「它对外承诺什么结果」，不写分支（分支属于失败表）。

```markdown
# 前
> 一句话：接单入口，校验后调用库存扣减并落库，失败时返回 500。

# 后
> 接单入口：校验 → 扣库存 → 落单，失败即整体回滚。
```

2.5 失败表：两列，处置枚举化

固定 症状 | 处置 两列，处置列用枚举词：致命-中止 / 降级-跳过 / 重试N次 / 忽略-记日志，告警并入处置词（如 致命-中止-告警）。处置列禁止写句子、禁止句号。

2.6 约束清单：同类合并，理由后置

「禁止…」「不得…」逐条展开理由会膨胀。做法：约束只写「不许做什么」，同类合并为一行；理由合并成一段放末尾一次说完。

2.7 一个事实一种符号

信息类型 唯一载体
摘要 引用块 >
结构化事实 表格
顺序步骤 有序列表
枚举/约束 无序列表，不加粗
代码/路由/schema 行内代码

规则：同一事实不跨载体重复；加粗只用于摘要引导词，强调靠位置而非字重。

2.8 正反例：只留正例 + 一行反例关键词

```markdown
正例：`③ 调用 O2 扣减库存`
反例关键词：把 O2 内部步骤写进本卡（展开下游）。
```

2.9 标题层级 ≤ 3 级

## 区块 → ### 卡片 → **字段组**（加粗代替四级标题）。折叠区内不再升级标题。

3. 代码块控制：坐标替代，折叠区收口

3.1 分级白名单

必须引用（唯一允许代码块）——字面值本身就是事实：

· SQL 语句、路由 / URL、Header / 配置键名、注解、MQ topic / 消息类型名。

禁止引用：函数体、语句块、控制流、变量声明、类定义、方法签名、任何 > 1 行的代码块。

允许行内：标识符级引用（orderService.deduct()、OrderStatus.FAILED）——是名词不是语句。

3.2 位置约束

字段 代码
摘要 / 处理逻辑 / 失败表处置列 ❌
关键事实 / 元信息表 ✅ 仅行内
折叠区 ✅ 可块（唯一允许贴多行代码处）

主阅读路径（折叠区外）零代码块——最直观的验收标准。

3.3 数量硬约束

· 单卡代码块 ≤ 1，且只在折叠区。
· 单段代码 ≤ 5 行，超出裁剪或改写为坐标。
· 全报告代码块总数 ≤ 卡片数。
· 行内代码每卡 ≤ 5 处。

3.4 替换手法

代码在干什么 别贴代码，这样写
一串 if 校验 校验 A/B/C 三项必填，缺失返回 400
try-catch 包调用 O2 失败时捕获异常转 503（不重试）
循环处理列表 逐条处理 items，单条失败跳过并累计错误数
构造请求对象 组装请求：orderId + items[] + 幂等键
事务包裹 @Transactional 包裹落库，异常回滚（OrderService.java:88）

原则：写「它做了什么」，不写「它是怎么写的」。

3.5 判据

删掉这段代码，结论还成立吗？ 成立 → 删，换坐标；不成立（字面值即结论）→ 保留但压到最小片段。

---

4. 坐标控制：锚点 + 风险配额

4.1 三层分级

层级 用途 密度 位置
L1 卡片锚点 本卡默认验证入口 每卡恰好 1 个 元信息表「主坐标」字段
L2 风险坐标 安全/并发/失败处理/隐式出站等高危结论 每卡 ≤ 2 个 折叠区或对应字段
L3 普通结论 其余全部 0 个 靠 L1 兜底

L1 是泄压阀——有了卡片级锚点，Agent 就不会每步补坐标。

4.2 合并规则

原始形态 压缩为
同文件相邻行 :88 :90 :93 :88-93 区间
同方法多处 :88 :102 :115 OrderService#createOrder（多处）
调用链 A:10 → B:20 → C:30 只留最外层 A.java:10

行号只出现「区间」或「单点」两种形态，不出现逗号列举。

4.3 路径压缩

· 报告开头声明一次相对前缀。
· 正文用短路径：service/OrderService.java:88。
· 文件名仓库内唯一时省略目录。
· 格式统一为 文件:行 或 文件:起-止，禁 L88、line 88、第88行。

4.4 禁止坐标的位置

一句话摘要内、处理逻辑每步后、失败表每行、元信息表非主坐标字段、补充说明。

4.5 数量硬约束

· 每卡坐标 ≤ 3（1 锚点 + 2 风险）。
· 全报告坐标 ≤ 卡片数 × 2。
· 处理逻辑区内坐标 = 0（折叠区除外）。
· 坐标 + 行内代码共享配额：每卡合计 ≤ 5 处（防止跷跷板效应）。

4.6 判据

删掉这个坐标，读者还能通过锚点找到吗？ 能 → 删；不能（跨卡片、锚点未覆盖）→ 保留但检查能否并入区间。

---

5. 统一输出前自检（合并去重，共 10 条）

Agent 输出前逐条机械核对：

1. 元信息表无空值（无 / N/A / 不适用 整行删除）。
2. 处理逻辑每步 ≤ 20 字，无箭头，无「然后 / 随后 / 接着」，≤ 5 步，不展开下游内部。
3. 失败表只有两列，处置列不含句号、不写句子。
4. 任一事实出现次数 ≤ 1（编号引用除外）；补充说明不复述卡片内容。
5. 加粗出现次数 ≤ 卡片数（每卡至多一处）。
6. 折叠区外无代码块；每段代码 ≤ 5 行；代码块总数 ≤ 卡片数。
7. 每卡首处坐标必为「主坐标」字段；每卡坐标 ≤ 3；处理逻辑区坐标 = 0。
8. 同文件多处已合并为区间或方法级；路径已去固定前缀、无 L88 变体。
9. 坐标 + 行内代码每卡合计 ≤ 5 处。
10. 删任一代码块 / 非锚点坐标后结论仍成立 → 该证据为不合格。

7. 优化效果预估

维度 优化前典型 优化后目标 降幅
单卡正文行数（折叠区外） 30–50 行 10–15 行 ~65%
代码块占正文比例 30–40% 0（主路径） 100%
坐标数量 每卡 5–8 处 每卡 ≤ 3 处 ~55%
全文篇幅 基准 — 50–60%
关键信息可读性 需通读全部卡片 Summary 覆盖 80% 显著提升

一句话总结：四层优化按「结构 → 字段 → 代码 → 坐标」递进，每层都有可机判的数量阈值和删除判据；骨架极简、证据配额、细节折叠，读者先拿到全局与每卡职责，再按需展开——报告的「信息密度」上升，「阅读负担」显著下降。
