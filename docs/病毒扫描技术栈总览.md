## 一、管道全景图

```
POST /api/files/upload
        │
        ▼
┌─ 预检（未落盘）StagingService ────────── 空文件 / 超大小 / 非白名单扩展名 → 400
        │
        ▼
┌─ 暂存落盘（UUID 命名）────────────────── 与 multipart 请求生命周期解耦
        │
        ▼
┌─ 阶段 1: Tika 类型校验 FileTypeValidator
│    ├─ 魔数探测 MIME（内容优先，文件名仅 hint）→ 白名单外 → REJECTED
│    ├─ MIME × 扩展名一致性（防张冠李戴）      → 不符    → REJECTED
│    └─ ZIP 炸弹四维流式检查（条目数/单entry/总量/压缩比，不递归）→ REJECTED
        │
        ▼
┌─ 阶段 2: ClamAV ClamAvScanner ────────── INSTREAM 推流 + 熔断器
│    └─ 已知病毒签名命中 → INFECTED（隔离区）
        │
        ▼
┌─ 阶段 3: YARA YaraScanner ────────────── CLI 子进程 + 自定义规则
│    └─ 定向规则命中（勒索话术/恶意宏特征/PDF自动JS）→ INFECTED（隔离区）
        │
        ▼
┌─ 阶段 4: 文档威胁检测 DocumentThreatScanner ── 仅文档格式执行
│    ├─ MACRO（OOXML 含 vbaProject.bin / OLE2 可疑宏）
│    │     ├─ BLOCK（默认）→ INFECTED
│    │     └─ FLAG         → 放行 + macro-flagged 打标
│    ├─ ACTIVE_X → INFECTED（始终拦截）
│    └─ PDF_ACTION（/Launch、/JS+/OpenAction）→ INFECTED
        │
        ▼
  CLEAN → 正式存储区 / INFECTED → 隔离区 / REJECTED、ERROR → 删除暂存
        │
        ▼
  同步：HTTP 响应 / 异步：SSE 推送（15s 心跳）+ 轮询兜底（Caffeine 缓存）
```

并发与韧性横切整个管道：虚拟线程承载 IO 密集扫描，入口 `Semaphore(16)` 统一背压，ClamAV 熔断器防故障级联，`fail-strategy` 决定引擎故障时拒绝（CLOSED，默认）或降级放行（OPEN）。

## 二、防御矩阵：每层挡什么

| 攻击场景 | 拦截层 | 结果 |
|---|---|---|
| exe/js/svg 伪装成 pdf/docx | 阶段 1 Tika | REJECTED 400 |
| 类型合法但扩展名张冠李戴 | 阶段 1 一致性校验 | REJECTED 400 |
| 已知病毒/木马（如 EICAR 验证链路） | 阶段 2 ClamAV | INFECTED 422 |
| 定向攻击、新样本（病毒库未收录） | 阶段 3 YARA 自定义规则 | INFECTED 422 |
| 恶意宏文档（AutoOpen + Shell） | 阶段 4（POI 提取宏源码）+ YARA 双保险 | INFECTED / FLAG |
| docm 伪装 docx / ActiveX / PDF 自动 JS、/Launch | 阶段 4 结构语义检测 | INFECTED 422 |
| ZIP 炸弹（高压缩比/海量entry/累计超限） | 阶段 1 四维流式检查 | REJECTED 400 |
| 超大文件 | multipart 限制 + 预检 + 同步阈值强制异步 | 413 / 400 / 202 |
| ClamAV 挂死/持续故障 | 熔断器 + fail-strategy | 快速失败 502 或降级打标 |
| 服务端细节泄漏 | 全局异常处理统一脱敏 | 通用错误码 |

## 三、为什么是四层：互补关系

单一检测引擎各有盲区，多层叠加的核心逻辑是**用不同原理的检测互相补位**：

| 引擎 | 原理 | 强项 | 盲区（由谁补） |
|---|---|---|---|
| Tika | 文件结构/魔数 | 内容级类型判定，挡伪装 | 不判"恶意"（阶段 2-4 补） |
| ClamAV | 已知签名库 | 覆盖广、自动更新 | 新样本滞后、不可定制（YARA 补） |
| YARA | 自定义签名 | 定向、当天可上线、业务语义 | 只认规则内特征（文档检测补） |
| 文档威胁检测 | 结构语义解析 | 不依赖情报更新、识别"构造异常" | 只懂文档格式（Tika+签名引擎补） |
| 签名引擎×2 共同盲区 | — | — | 宏压缩存储、PDF 压缩对象流（POI 真实解压、ClamAV PDF 解析分头补） |

分层还带来工程收益：每层独立可测（单测分别覆盖）、独立可关（`yara.enabled`、`macro-policy`）、独立失败域（子进程/容器/线程隔离）。

## 四、代码索引

| 管道阶段 | 类 | 职责 |
|---|---|---|
| 预检+落盘 | `service/StagingService` | 大小/扩展名预检，暂存落盘 |
| 阶段 1 | `service/FileTypeValidator` | Tika 探测 + 一致性 + ZIP 四维炸弹检查 |
| 阶段 2 | `service/ClamAvScanner` | INSTREAM 客户端 + Resilience4j 熔断 |
| 阶段 3 | `service/YaraScanner` | yara CLI 子进程封装 + 规则路径解析 |
| 阶段 4 | `service/DocumentThreatScanner` | OOXML/OLE2/PDF 结构威胁检测 |
| 管道编排 | `service/VirusScanService` | 信号量背压、短路顺序、生命周期收口、fail 策略 |
| 异步分发 | `service/AsyncScanProcessor` | 虚拟线程执行 + SSE/轮询 + Caffeine 缓存 |
| 存储/隔离 | `service/FileStorageService` | 正式入库、隔离区（权限收敛） |
| 配置 | `config/VirusScanProperties` | 全部策略开关与阈值 |
| 健康 | `support/ClamAvHealthIndicator` | ClamAV PING → /actuator/health |
| 规则 | `src/main/resources/rules/malware.yar` | YARA 基线规则（三条） |
| 引擎部署 | `docker/docker-compose.yml` | clamav 1.4.5 容器 |

## 五、学习文档导航与推荐顺序

| 文档 | 内容 | 前置知识 |
|---|---|---|
| [Tika文件类型检测详解](Tika文件类型检测详解.md) | 魔数原理、检测链、API、白名单行为 | 无（最易入门） |
| [ClamAV病毒扫描引擎详解](ClamAV病毒扫描引擎详解.md) | 架构、签名库、INSTREAM 协议、熔断器、Docker 运维、EICAR | 建议先读 Tika |
| [YARA恶意软件规则匹配详解](YARA恶意软件规则匹配详解.md) | 规则语法、本项目三条规则解读、CLI 退出码语义、误报控制 | 建议先读 ClamAV（理解分工） |
| [文档威胁检测详解](文档威胁检测详解.md) | OLE2/OOXML/PDF 格式、宏攻击链、压缩盲区、ZIP 炸弹四维防护 | 建议先读 YARA（规则与结构检测互补） |

**推荐学习路径**：按管道顺序（Tika → ClamAV → YARA → 文档威胁）即由浅入深：Tika 只需理解魔数；ClamAV 加入网络协议与韧性模式；YARA 引入一门规则语言；文档威胁检测综合文件格式规范知识。每篇文档末尾都有动手实验，可边读边在本地验证。

**验证环境速记**：

```bash
docker compose -f docker/docker-compose.yml up -d clamav   # 起杀毒引擎
mvn spring-boot:run                                        # 起应用
mvn verify                                                 # 含 EICAR 端到端（需 Docker）
```
